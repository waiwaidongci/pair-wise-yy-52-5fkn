# 风电场检修隔离与作业许可协调平台

源提示词编号：9。覆盖风机、箱变和线路隔离点、锁定与验电步骤、作业许可状态流、跨班组冲突检测、实时提醒、断线重连、失败操作重试和审计记录。

## 技术栈

Nuxt 3、Nuxt UI、Pinia、Nuxt Router、TanStack Query、ofetch、WebSocket 模拟、TypeScript。

## 统一重算链路

许可步骤、许可状态、隔离点状态、班组占用、留痕不再各自维护判断，而是全部汇入同一条重算链路（`utils/recompute.ts`，store 中唯一入口 `runChain`）：

- **跨班组共享隔离资源 + 作业窗口重叠** → 硬冲突，受影响许可**立即退回「待复核」**，并按资源合并生成「待负责人协调」项；
- **同班组资源/窗口重叠** → 软冲突，仅提示不强制退回；
- **隔离边界变化** → 完成时绑定了边界快照（`dependsOnBoundary`）的步骤**结果作废、证据保留**，需按新边界重新确认；**已完成许可同样退回**；
- **协调放行**锁定边界签名，边界再变则决策自动失效、协调项重开、许可再次退回；
- 每一次退回、作废、协调项变化都写入审计时间线。

## 断网恢复合并（`utils/sync.ts`）

1. 断网时保存基线快照，本机步骤与推进意图进入本机 outbox（记录所依据的 `baseRevision`）；
2. 重连后先应用对端在断网期间的推进，再把本机 outbox **按时间顺序**重放；
3. 对端已越过本机版本且改动了**同一字段**（状态 / 同一步骤 / 同一隔离点）时，**过期操作不得覆盖新状态**，转入待处理项由值班负责人协调；改其他字段走三路合并；
4. 已被重算退回「待复核」的许可，其断线期间推进意图一并作废；
5. 顶栏「模拟断网 / 模拟对端推进 / 重连合并」可演示完整过程。

## 本地数据升级（`utils/migration.ts`）

存储键升级为 `yy52-permit-ops-v2`。检测到旧 `yy52-permit-ops-v1` 数据时自动迁移：推断隔离资源、补齐冲突/作废字段、重新跑一遍重算；旧键保留为 `.bak`，损坏数据不阻断启动。
